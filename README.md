# Domeo Spec Converter

Сервис для просчёта спецификаций: берёт PDF тома «Технологические решения» (раздел ТХ
проектной документации), вытаскивает из него спецификацию технологического оборудования
и выгружает её в Excel по форме приложения к договору (спецификация к КП).

Это **этап 1** конвейера «PDF → спецификация → цены → КП». Следующие этапы (сверка с
чертежами, подбор по базе 1С, поиск цен) описаны в [docs/PLAN.md](docs/PLAN.md).

## Что умеет сейчас

- Находит в PDF листы спецификации (по шапке таблицы: «Поз.», «Наименование», «Кол-во»…),
  читает строки с любой ориентацией листа и любым проектировщиком — формат не захардкожен.
- Разбирает помещения/разделы (заголовки «1.01 Групповая комната…», «ПИЩЕБЛОК»),
  многострочные описания, переносы описания на следующую страницу.
- Отбрасывает штампы «В производство работ», подписи Диадока и основную надпись листа.
- Сводит одинаковые позиции из разных помещений в одну строку с общим количеством.
- Интерфейс для менеджера: несколько томов одного объекта (ТХ1 + ТХ2) в одной спецификации;
  свод редактируется прямо в таблице — раздел КП (с подсказками из образца), наименование,
  характеристики, единица, количество, цена за единицу; лишние позиции исключаются из КП
  (например, «закупается образовательной организацией»), раздел назначается массово;
  правки сохраняются в браузере.
- Формирует КП по образцу заказчика: книга с листами «1» (Приложение №1.1, товар с
  монтажом, графы СМР) и «2» (Приложение №1.2, инвентарь без монтажа); какая позиция на
  каком листе — галочка «Монтаж» в своде. Параметры (договор, должности подписантов, НДС,
  наценка, доставка, СМР, округление) — во вкладке «Формирование КП», цена в КП считается
  поверх базовой цены каждой позиции, итоги видны сразу.
- Себестоимость для Домео (вкладка «Себестоимость»): на сервер загружается выгрузка 1С
  «Заказы поставщикам» (xlsx), из неё собирается прайс закупки — наборы сводятся к цене
  комплекта, выбросы отсекаются. Позиции свода сопоставляются с прайсом (точно / похоже /
  аналог по словам); у каждой видны минимум, максимум и последняя цена по истории с
  раскрытием кандидатов и покупок. Оператор щёлкает нужную цену (или массово «везде
  минимум / медиану / максимум / последнюю»), она становится базовой для КП. Выгрузка
  «Себестоимость» — лист с тремя ценовыми графами, выбранной ценой и её источником плюс
  листы «Покупки по истории» и «Предложения из интернета».
- Цена с рынка на дату (графа «Интернет на дату»). По умолчанию — **автопоиск,
  бесплатно**: при открытии вкладки «Себестоимость» позиции сами сопоставляются с историей
  и ищутся у поставщиков; той, по которой в индексе меньше трёх разных магазинов (порог —
  настройка), ядро ищет в интернете обычным поисковиком без ключей и оплаты (DuckDuckGo и
  другие через библиотеку ddgs), читает
  найденные страницы магазинов по разметке, а сами магазины заводит в «Поставщики» и ставит
  их каталоги в очередь на обход — индекс растёт сам. Показываются до 6 предложений
  (поставщик, цена, ссылка, совпадение в процентах, дата) и медиана по совпавшим;
  найденное кэшируется на 7 дней. Поставщиков можно добавить и вручную: сайт (обход —
  фид YML, карта сайта, ссылки) или прайс-лист xlsx. **Платный вариант** остаётся: с ключом
  `ANTHROPIC_API_KEY` модель Claude ищет предложения сама. Щелчок по предложению делает
  его ценой с рынка, щелчок по цене — базовой для КП.
- Рабочая выгрузка для себя: **Спецификация** (форма 1.1 с базовыми ценами),
  **По помещениям** (построчно, как в PDF), **Проверка** (что не прочиталось, по каждому тому).
- Сканы без текстового слоя: страница растрируется, линии таблицы находятся на картинке,
  текст распознаётся Tesseract'ом и идёт по тому же конвейеру. Без установленного
  Tesseract такие страницы помечаются как пропущенные.

## Устройство

```
web (React) ──► api (ASP.NET Core 9) ──► core (Python, FastAPI)
                 обвязка: контракт API,      ядро разбора: PDF → строки,
                 позже 1С, цены, КП          свод, Excel, OCR
```

| Часть | Стек | Роль |
|---|---|---|
| `core/` | Python 3.12, FastAPI, PyMuPDF, openpyxl, pytesseract | внутренний сервис разбора; наружу не смотрит |
| `api/` | ASP.NET Core 9, Clean Architecture (Domain / Application / Infrastructure / Api) | единственный вход для фронта; сюда встанут 1С, цены, КП |
| `web/` | React 19 + Vite + TypeScript, Mantine | интерфейс |

Ядро оставлено на Python из-за PyMuPDF (координаты текста и векторных линий) и задела
под OCR и сопоставление с номенклатурой через LLM. Вся бизнес-обвязка — на C#, как в
остальных сервисах Domeo.

## Запуск

Одной командой (Windows): `dev.cmd` в корне репозитория поднимает все три части в отдельных
окнах и открывает http://localhost:5180. Ниже — то же по отдельности.

Ядро разбора:

```bash
cd core
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

API (адрес ядра — `Engine:BaseUrl` в `appsettings.json`):

```bash
cd api
dotnet run --project src/DomeoSpec.Api
```

Фронтенд (в разработке проксирует `/api` на порт 5080):

```bash
cd web
npm install
npm run dev
```

Открыть http://localhost:5180. Для продакшена `npm run build` — собранный `web/dist`
раздаёт сам API, отдельный веб-сервер не нужен.

Разбор из командной строки без веб-интерфейса:

```bash
cd core
python -m app.cli "путь/к/тому-ТХ.pdf" результат.xlsx
```

## Стенд на ВМ

`deploy/` — compose из трёх контейнеров: `core` (Python + Tesseract), `api` (ASP.NET Core со
встроенным фронтом), `edge` (nginx с лимитами и наружным портом; без пароля — по решению
заказчика, доступ ограничивается только security group). Выкат:

```bash
deploy/deploy.sh
```

Образы собираются локально (нужен Docker Desktop) и уезжают на ВМ через
`docker save | ssh docker load` — реестр не нужен. Хост и порт: `DEPLOY_HOST` (по умолчанию
`testvm` из `~/.ssh/config`), `EDGE_PORT` (8090).
Логи: `ssh testvm 'cd ~/domeo/spec && docker compose logs --tail 100'`.

На ВМ хранятся только прайс закупки, индекс поставщиков и кэш интернет-цен (том
`core_data`; переживает пересборку образов). Разобранные PDF и правки живут в браузере пользователя, на сервере не
остаются; загруженная выгрузка 1С после сборки прайса удаляется.

**Обновление стенда — только выкатом.** На ВМ работают образы, собранные в момент
`deploy.sh`; изменения в репозитории туда сами не попадают. Порядок: закоммитить →
`bash deploy/deploy.sh` (одна-две минуты). Автовыкат по push в `main` можно добавить
GitHub Actions по образцу release.yml дизайнерского бэкенда — понадобится SSH-ключ ВМ в
секретах репозитория.

**Публичный адрес** https://testdesign.domeohome.ru/spec/ — это stage-nginx дизайнерской
платформы на той же ВМ (`~/domeo/stage/nginx.conf`, не в этом репозитории): `location /spec/`
проксирует на наш край `172.18.0.1:8090`, `/spec/assets/` — статика, `/api/specifications/`
— ручки приложения (лимит 100 МБ, тайм-аут 600 с). Поэтому все ручки приложения живут под
`/api/specifications/*`, включая health; `/api/health` на общем домене принадлежит другому
сервису.

## OCR для сканов

Нужен Tesseract с русским языком: Windows — установщик UB-Mannheim
(`winget install UB-Mannheim.TesseractOCR`, при установке отметить Russian),
Linux — `apt install tesseract-ocr tesseract-ocr-rus`. Бинарник `tesseract` должен быть в
`PATH`. Проверка: `GET /api/health` возвращает `"ocr": "tesseract"`.

```

```

Python: синтетический PDF работает всегда; тесты на реальных документах читают

## API (ASP.NET Core, порт 5080)

Ответы — конверт `{ success, data, message, errors }`, ошибки — RFC 7807 ProblemDetails
с полем `code` (`validation_failed`, `engine_failed`, `service_unavailable`).

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | состояние API и ядра (`engine.available`, `engine.ocr`) |
| `POST` | `/api/specifications/parse` | multipart `file` (PDF) → `ParsedDocument` |
| `POST` | `/api/specifications/export` | `ParsedDocument` (можно отредактированный) → `.xlsx`; `kind`: `kp` / `cost` / `working` |
| `GET` | `/api/specifications/pricelist` | сводка по загруженному прайсу закупки (`data: null`, если не загружен) |
| `POST` | `/api/specifications/pricelist` | multipart `file` (xlsx-выгрузка 1С) → прайс закупки пересобран и сохранён |
| `POST` | `/api/specifications/pricelist/match` | `{ items: [{ id, name, description }] }` → `{ matches: { id: HistoryPrice } }` |
| `GET` | `/api/specifications/internet` | поиск цен в интернете: настроен ли ключ, модель, размер кэша |
| `POST` | `/api/specifications/internet/lookup` | `{ items: [{ id, name, description, unit }], refresh }` (до 50) → `{ lookups: { id: InternetLookup } }` |
| `GET` | `/api/specifications/suppliers` | поставщики и размер индекса цен |
| `POST` | `/api/specifications/suppliers` | `{ name, site, max_pages }` → поставщик |
| `DELETE` | `/api/specifications/suppliers/{id}` | убрать поставщика и его цены |
| `POST` | `/api/specifications/suppliers/{id}/crawl` · `/stop` | запустить / остановить обход сайта (в фоне, прогресс в списке) |
| `POST` | `/api/specifications/suppliers/{id}/pricelist` | multipart `file` (xlsx) → цены поставщика из прайса |
| `GET` | `/api/specifications/suppliers/{id}/sample` | примеры собранных позиций |

Swagger API: http://localhost:5080/swagger. Внутренний API ядра (8000): `/api/parse`,
`/api/export`, `/api/pricelist`, `/api/pricelist/match`, `/api/internet`,
`/api/internet/lookup`, `/api/suppliers*`, `/api/health`, Swagger на http://localhost:8000/docs.
Прайс закупки, индекс поставщиков и кэш интернет-цен ядро хранит в `DATA_DIR`
(`pricelist.json`, `suppliers/`, `internet_prices.json`; по умолчанию `core/.data/`, в
контейнере — том `/data`).

## Цены с рынка: поставщики (бесплатно) или веб-поиск моделью (платно)

Источник выбирается переменной ядра `PRICE_SEARCH_PROVIDER`: `auto` — индекс поставщиков плюс
бесплатный автопоиск в интернете, `suppliers` — только индекс, `claude` — веб-поиск моделью,
`fake` — заглушка с выдуманными ценами для показа интерфейса. Без переменной: `claude`, если
задан `ANTHROPIC_API_KEY`, иначе `auto`.

**Автопоиск.** Поисковик — `WEB_SEARCH_ENGINE`: `ddgs` (по умолчанию; `WEB_SEARCH_BACKEND` —
`auto`, `duckduckgo`, `bing`, `yandex`…), `searxng` (свой метапоиск, `SEARXNG_URL`) или `off`.
Запрос — «наименование позиции купить», не чаще одного в полторы секунды; маркетплейсы,
объявления, видео и соцсети пропускаются; читаются до 8 страниц, не больше двух с одного
сайта, robots.txt уважается. Найденные магазины появляются в «Поставщиках» с пометкой
«автопоиск» и обходятся в фоне по очереди — глубину задаёт настройка «Обходить найденные
сайты, страниц» (по умолчанию 300, 0 — не обходить). В интернет позиция идёт, пока по ней в
индексе меньше N разных магазинов с той же позицией (настройка «Искать в интернете, пока
по позиции меньше магазинов», по умолчанию 3): так у оператора картина рынка, а не одна
цена. Кэш запросов — `web_search_cache.json` в `DATA_DIR`, повтор той же позиции в течение
недели поисковик не трогает.

**Поставщики.** Окно «Поставщики» (кнопка вверху): название + сайт или только название и
прайс xlsx. Обход сайта идёт в фоне: сначала фид YML (`/yml.xml` и похожие), потом карта
сайта из robots.txt / `sitemap.xml`, потом переходы по ссылкам; цена берётся из разметки
страниц (schema.org JSON-LD, микроразметка, OpenGraph, в крайнем случае h1 + цена).
Не чаще двух запросов в секунду, robots.txt уважается, лимит страниц задаётся на
поставщика. Прайс xlsx: шапка со словами «наименование»/«цена» ищется сама, иначе колонки
угадываются по содержимому. Сайты без разметки цен и с подгрузкой на JavaScript обходом не
берутся — для них прайс-лист.

**Веб-поиск моделью.** Нужен ключ Claude API. Ядро читает его из окружения: локально
положите строку `ANTHROPIC_API_KEY=sk-ant-...` в файл `core/.env` (в git не попадает), на
стенде — в `deploy/secrets.env` рядом с compose на ВМ (compose подхватывает, `deploy.sh`
файл не трогает). Настройки: `PRICE_SEARCH_MODEL` (по умолчанию `claude-opus-5`;
`claude-sonnet-5` — примерно вдвое дешевле), `PRICE_SEARCH_EFFORT` (`medium`),
`PRICE_SEARCH_MAX_SEARCHES` (4 поисковых запроса на позицию), `INTERNET_PRICE_TTL_DAYS` (7),
`INTERNET_PRICE_CONCURRENCY` (3 позиции одновременно).

Ориентир расходов: на позицию уходит 2–4 поисковых запроса и ~15–20 тыс. токенов — порядка
10–15 ₽ на Opus 5 (на Sonnet 5 — вдвое меньше); объект на 200 позиций — ~2–3 тыс. ₽ при
первом просчёте, повторы в течение 7 дней бесплатны (кэш). После поиска интерфейс показывает,
сколько запросов ушло, — по ним удобно сверить оценку с реальным счётом.
