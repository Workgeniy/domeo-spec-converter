# История КП и целевая маржа

## Работа менеджера

При нажатии «Сформировать КП» API сначала создаёт Excel и сохраняет неизменяемую версию в PostgreSQL, затем браузер скачивает файл. Ошибка базы не выдаётся за успешное сохранение: рабочие правки остаются в браузере, запрос можно повторить. Рабочая выгрузка, себестоимость и проверка шаблона в историю не попадают.

Кнопка «История КП» доступна и без открытого объекта. Поиск — по названию объекта и договору, фильтр — текущий объект, страницы — по 30 версий. «Скачать Excel» возвращает ранее сохранённые байты, без вызова Python. «Открыть и редактировать» восстанавливает свод, исключённые строки, цены, параметры поиска, исходные Excel-файлы, выбранную форму, договор, маржу и индексацию. Новое формирование сохраняет новую запись с ссылкой на исходную версию. Предыдущая запись не перезаписывается.

В истории КП сохраняются сформированные предложения; исходники теперь сохраняются отдельно сразу при загрузке. Несформированные правки автоматически сохраняются в рабочем объекте в БД, раздел «Объекты». Ранее скачанные КП автоматически не импортируются. Новые PDF, XLSX и XLSM сохраняются в архиве «Документы» до разбора, без формирования КП. Планы для сверки тоже сохраняются при выборе. Архив содержит оригинальные байты, имя, размер, SHA-256, объект, дату и результат разбора или его ошибку. Повтор того же файла в том же объекте не создаёт дубль; новые байты с прежним именем дают отдельную запись. Доступные исходники старого локального черновика переносятся из IndexedDB в архив при первом автосохранении; утраченные локальные файлы нужно загрузить повторно.

В архивном объекте серверный справочник индексации и автоматический поиск цен не заменяют сохранённые значения. Дата начала расчёта индексации закрепляется в `base_date`; кнопка «Пересчитать от сегодня» обновляет её явно.

## Маржинальность

Единая целевая маржа для всех товаров КП задаётся на вкладке «Формирование КП → Правила расчёта». Допустимо 0–99,99%. `null` означает прежний режим наценки; старые черновики мигрируют в этот режим без изменения цен. Новые рабочие пространства по умолчанию используют маржу 0%.

Цена товара = база × (1 + доставка / 100) ÷ (1 − маржа / 100).

При базе 100 ₽, доставке 10% и марже 20%: цена 137,50 ₽. Наценка 90%, оставшаяся от прежнего режима, дополнительно не применяется. СМР начисляется отдельно процентом от продажной цены товара. Целевая маржа здесь относится к товару и расчётным расходам на доставку; себестоимость СМР и накладные расходы не заданы. Позиции без цены/количества не участвуют в сумме. Округление может изменить фактический процент.

В служебной графе «пр» старых Excel-форм остаётся эквивалент наценки: маржа 20% → наценка 25%. Шапка и форма шаблона сохраняются. Предпросмотр и Excel используют одинаковый порядок арифметических операций и округления.

## Хранение и запуск

На сервере используется существующий PostgreSQL, отдельная база и пользователь. Дополнительные PostgreSQL, Redis и MinIO для этой функции не запускаются. Npgsql 9.0.3, пул максимум 5 соединений; нулевой минимальный пул. Схема создаётся идемпотентно при первом обращении, под транзакционной advisory-блокировкой.

В автономном десктопе то же хранилище работает на встроенном SQLite (`SqliteQuotationStore`, движок внутри процесса, без отдельной службы БД) — реализацию выбирает DI по строке подключения (`Data Source=…` → SQLite, `Host=…` → PostgreSQL). Таблицы и логика те же; подробности и разовый перенос старых данных — в `docs/ARCHITECTURE.md`, раздел «Два хранилища».

Таблица `spec_quotations`: идентификаторы версии/объекта/родителя, дата UTC, название, договор, число позиций, маржа, имя формы/файла, хеш запроса, JSONB-снимок и BYTEA готового Excel. Список выбирает только метаданные, без больших JSON и файлов. Один INSERT атомарно сохраняет снимок и Excel. UUID запроса защищает повтор после обрыва сети от дубля; попытка использовать тот же UUID для другого содержимого отклоняется.

Начальный вариант хранит файлы в БД ради атомарности и простой резервной копии. Объём диска растёт с количеством версий; новые исходники хранятся один раз в `spec_uploads`, снимки КП ссылаются на них через `original.upload_id`. Старые снимки с base64 остаются совместимыми; выбранная форма по-прежнему сохраняется в каждом снимке. При росте архива можно вынести бинарные файлы в существующий MinIO, оставив ссылки и контрольные суммы. Снимки версионированы (`version=1`).

Локально: `api/src/DomeoSpec.Api/appsettings.Local.json` содержит `ConnectionStrings:Quotations`. Файл читается только в Development, игнорируется Git, исключён из Docker-контекста и публикации. Переменная окружения `ConnectionStrings__Quotations` имеет приоритет. Пароли не помещать в отслеживаемые файлы.

На ВМ: в `deploy/database.env` задать `ConnectionStrings__Quotations=Host=...;Database=...;Username=...;Password=...`. Адрес должен быть доступен из контейнера API; сетевое подключение к существующему PostgreSQL настраивается при выкладке. Конвертер не меняет пользователей или базы соседних приложений. В рамках внедрения ВМ не обновлялась.

Резервное копирование: включить отдельную БД в существующее расписание `pg_dump -Fc`, хранить копии за пределами диска ВМ и проверять восстановление через `pg_restore` в отдельную БД. Пока резервное копирование не настроено, история переживает перезапуск приложения, но не потерю диска PostgreSQL. Доступ к истории общий для пользователей приложения; разграничение по сотрудникам не добавлялось.

## API

- `GET /api/specifications/quotations?search=&projectId=&offset=0&limit=30` — метаданные версий; лимит 1–100.
- `POST /api/specifications/quotations` — `{id, project_id, parent_id, snapshot}`; формирование и атомарное сохранение.
- `GET /api/specifications/quotations/{id}` — метаданные и полный снимок для редактирования.
- `GET /api/specifications/quotations/{id}/file` — точные байты сохранённого XLSX.

JSON snake_case; ключи словарей (названия разделов и идентификаторы строк) сохраняются буквально. Максимальный HTTP-запрос 100 МиБ, клиент проверяет 95 МиБ до отправки. Архив без подключения к БД возвращает явную ошибку 503.

## Проверки

`dotnet test api/DomeoSpec.sln`: сценарии API с подставным Python, сохранение, восстановление, повтор, новая версия, ошибки и границы маржи. Для интеграционного теста PostgreSQL установить `TEST_QUOTATIONS_CONNECTION` на отдельную тестовую БД: проверяются параллельные повторы, чтение новым экземпляром хранилища, точные байты и индексы страниц; тест очищает только собственный проект.

`cd core && python -m pytest`: прежняя наценка, новая маржа, доставка, СМР, стандартный/пользовательский шаблон и фиксированная дата индексации. `cd web && npm run build` проверяет TypeScript и сборку.

## Архив исходников (09.10.2026)

Входной поток интерфейса: POST uploads (сохранение байтов) → POST uploads/{id}/parse (разбор и сохранение результата) → рабочее пространство. Ошибка разбора не удаляет оригинал. При недоступной БД загрузка явно завершается ошибкой, без обещания сохранности. Позже открывается сохранённый результат разбора, без вызова ядра; для неразобранного документа доступна повторная попытка.

Таблица `spec_uploads`: `id`, `project_id`, `created_at`, `file_name`, `title`, `size`, `sha256`, `content_type`, `content` (BYTEA), `document` (JSONB, nullable), `error`. Уникальность `(project_id,file_name,sha256)` защищает в том числе параллельные повторы. Список читает только метаданные. Архив и история используют один пул максимум 5 соединений и одну БД; резервная копия всей БД включает оригиналы.

- `POST /api/specifications/uploads` — multipart `file`, `projectId`, `title`; PDF/XLSX/XLSM до 100 МиБ, сохранение до разбора.
- `GET /api/specifications/uploads?search=&offset=0&limit=30` — поиск по имени/объекту, метаданные, до 100 записей на страницу.
- `GET /api/specifications/uploads/{id}` — сведения и сохранённый результат разбора.
- `GET /api/specifications/uploads/{id}/file` — исходный файл без преобразования.
- `POST /api/specifications/uploads/{id}/parse` — возвращает уже сохранённый результат либо разбирает оригинал и сохраняет его. Поздняя ошибка параллельного запроса не затирает успешный результат.

Старый `/parse` остаётся совместимым техническим маршрутом без архива; основной интерфейс использует `/uploads`. Новый `QuotationSource.upload_id` — ссылка на оригинал, `content` в этом случае пустая строка. Удаления файлов из общего архива в интерфейсе нет. Архив исходников содержит первоначальный файл и результат разбора; текущие правки менеджера хранятся отдельно в рабочем объекте, а сформированные Excel — в истории КП.


## Рабочие объекты и автосохранение

«Объекты» — общий список рабочих документов этого сервера с поиском, датой изменения,
количеством томов/позиций и маржой. После успешного разбора первого файла объект появляется
автоматически. Сохраняются название, все тома и исключённые строки, правки/количества/цены,
результаты поиска цен, договор, маржа и остальные параметры КП, ставки и дата индексации,
содержимое выбранного шаблона, ссылки на исходники и последнюю связанную версию КП.

Через секунду после последней правки клиент отправляет текущий снимок. Индикатор
«Все изменения сохранены» появляется только после ответа БД. «Закрыть объект» и открытие
другого объекта сначала дожидаются сохранения. При ошибке переход не выполняется; при
сетевом сбое запрос повторяется через 15 секунд и при восстановлении сети. В одном окне
одновременно выполняется один запрос; правки во время отправки уходят следующей записью.

Открытие на другом компьютере восстанавливает снимок из БД. Чистый локальный кэш при
перезагрузке обновляется с сервера, локальные несохранённые изменения пытаются сохраниться
с исходной ревизией. localStorage — резервный кэш, а не источник истины. При переполнении
кэша показано предупреждение; при незавершённом сохранении браузер предупреждает о закрытии.
Нельзя гарантировать сохранение последних нажатий при аварийном закрытии/потере питания:
дождитесь серверного подтверждения. Потеря ответа с последующей перезагрузкой может дать
конфликт собственной прежней записи — данные автоматически не затираются.

Каждая запись проверяет `expected_revision` атомарно, под блокировкой PostgreSQL по объекту.
Устаревшее окно получает HTTP 409. Можно открыть серверный вариант с явным подтверждением
замены локальных правок либо сохранить свои правки отдельной копией. Это защита от потери
работы, без одновременного редактирования строк и автоматического объединения изменений.
Пользователи/права доступа и авторство пока общие для всего экземпляра приложения.

«Документы → Создать объект» создаёт новый объект из первоначального разбора и не заменяет
существующий рабочий объект. «История КП → Открыть и редактировать» по явному подтверждению
возвращает рабочий объект к выбранному снимку; готовые Excel остаются неизменяемыми.
Автосохранение хранит одну текущую рабочую запись, не архив каждого нажатия клавиши.
Результаты сверки с планом, фильтры таблиц и выбранная вкладка в этот снимок не входят;
сам выбранный файл плана уже хранится в общем архиве документов.

### API объектов

- `GET /api/specifications/projects?search=&offset=0&limit=30` — метаданные; поиск по названию, до 100 записей.
- `GET /api/specifications/projects/{id}` — `{info,snapshot}`, версия снимка 1.
- `PUT /api/specifications/projects/{id}` — `{expected_revision,mutation_id,snapshot,quotation_id}`.
  Ревизия 0 создаёт новый объект, успешное изменение увеличивает ревизию на 1. Точный повтор
  последнего `mutation_id` с тем же содержимым возвращает прежний результат. Старая ревизия
  или повтор идентификатора с иными данными — 409. Пустой объект после удаления всех томов
  тоже сохраняется. Оригиналы — ссылки `upload_id` на архив, без повторения байтов.

`spec_projects`: UUID, bigint revision, updated_at, title, documents/positions,
margin_percent, quotation_id, mutation_id, request_hash и JSONB snapshot. Список не читает
JSONB. Используется существующая БД и тот же пул максимум 5 соединений; новых сервисов нет.
Таблица создаётся идемпотентно вместе с таблицами архива. Резервная копия БД включает все три.

Проверки: `npm test` в web (очередь, потеря ответа, конфликт и копия, переходы, перезагрузка),
`dotnet test api/DomeoSpec.sln` (контракт API и PostgreSQL). Для проверки настоящей БД задайте
`TEST_QUOTATIONS_CONNECTION` на отдельную тестовую базу; тесты удаляют только свои UUID.
